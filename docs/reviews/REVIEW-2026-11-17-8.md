## Summary

**Round 7 is fixed and nothing has regressed.**
- `useControlsSync` now binds the token to the session.
- `AuthProvider`'s `storage` handler clears `user` and sets `loading` until `/users/me` confirms the new user.
- An anonymous write clears the marker.
- Uploads are serialised.
- `review7.test.tsx` covers these cases and passes.

**The F020 server side is correct.**
- **Slow-mode claim:** it is a single `BEGIN IMMEDIATE` transaction. The claim upsert runs first, then the top-level insert or the F017 guarded reply insert. If either affects 0 rows, the transaction rolls back before the F017 re-read. A rejected post therefore never uses up the slot, and two concurrent posts serialise on the write lock.
- **Validation order:** it matches API § F020 (5b mode → 6 parent → 6b lock → 6c slow mode → 7 cap).
- **Exemption:** `is_admin` is loaded at most once per request.
- **`PUT …/comment-settings`:** the order is 401 → 400 → 404 (`fetch_visible_game`) → 403 → 429 → 422, and validation is strict (`as_i64` rejects `60.0`, `"60"` and `true`).
- **Privacy:** `waitSecs` is computed only for the viewer's own row. Another user's post times are never exposed.

One low edge remains: after a server clock step backwards, the real block can last longer than the `Retry-After` the server reports (L1).

**The F020 UI follows the spec**, including the § 2.4 table, the `aria-disabled` submit, a single end announcement and the monotonic deadline. One low accessibility issue: focus is lost when the settings form disables its focused Save button (L3).

**F019 has one real key leak (M1).** Typing on a focused, not-yet-editing text field starts editing in that step, but keyboard capture only starts in the next step. `engine.ui.editing` is also still `null` before the field's call in that step. So the first typed letter still fires its action, and the guard GAME_FORMAT recommends (`!engine.ui.editing`) misses it.
- **Repro:** in the shipped Menu & HUD template, open SETTINGS with the keyboard (focus lands on NAME) and type "P". The first letter is typed, and `pause` exits the settings screen in the same step. Reproduced in a scratch test.

Other capture checks:
- **Stuck capture:** a game can't get stuck in capture mode. Capture is recomputed in every `endStep`, and editing is dropped whenever the field isn't declared or is disabled.
- **Keys held when capture ends:** they are latched until released.
- **The Escape lead:** confirmed as a known browser behaviour. It has low impact and is documented only in the spec (L2).

**New examples (light review).**
- Both `game.json` files pass the F009 action rules and the achievement rules. Every `unlockAchievement` id is declared, and every engine API name the games use exists.
- The packed zips match their sources.
- Both games break the GAME_FORMAT "mute at load" rule. Their title scene runs `loadProfile` on every `enter`/`resume`, and `loadProfile` sets `engine.audio.muted = !settings.sound`. This undoes the site's mute button each time the player returns to the title screen (M2).
- The renderer fix looks correct, but it has no test (L4).

Also noted, below the bar for a finding:
- **The countdown and system sleep.** The deadline uses `performance.now()`, which on macOS doesn't advance while the machine sleeps. After a lid-close, the countdown can show more time than the server will enforce. That errs on the safe side, and the next page-1 load corrects it. Windows and WebView2 are unaffected.
- **A stale countdown after the owner turns slow mode off.** Another player's tab keeps `aria-disabled` until its local deadline ends. This is self-correcting and within the documented "settings races".
- **The lock-race wording.** API § F020 notes says a thread locked between the check and the transaction "fails with `slow_mode` instead of the lock error". That happens only when the poster is also waiting under slow mode. Otherwise the guarded insert returns 0 rows and the F017 re-read gives the lock error. The sentence is accurate but reads as unconditional.
- **The ARCHITECTURE wording of the claim.** It says "deferred transaction … takes the write lock at once", but the code uses `BEGIN IMMEDIATE`, which is stronger and fine.
- **Kiln Clash training mode** unlocks `kiln_burst`, `ten_hit` and `clean_break` against a dummy with infinite meter (`kiln-clash/main.js:2941-2945`). This is deliberate (an explicit `training` branch) and makes those achievements trivial. It's a design call for the author.
- **Example prompts** use `keyLabel(a.keys[0])`, not the F016 device-aware `actionLabel(id, "auto")`, so HUD prompts don't switch to pad buttons. This is optional, but these are the showcase examples.
- **Alt+letter while editing.** On Windows, a non-AltGr Alt+letter types the letter and is `preventDefault`ed, which blocks browser Alt shortcuts while a field edits. This matches the GAME_FORMAT rule (only Ctrl/Meta are excluded).
