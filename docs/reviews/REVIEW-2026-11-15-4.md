## Summary

**The round-3 fixes hold.** M1, M2, L1–L8 and L10 are fixed. L9 is partly fixed: desktop `cargo test` now runs in CI, but there is still no desktop fmt or clippy. L11 was fixed, but the README has gone stale again since. One fix went too far: L5 now refunds the screenshot quota on 422 decode failures as well as on 503. That reopens an unmetered decode path (new M2).

**F009 is solid on the security side.**
- `/play` renders the actions from the *parsed and re-serialised* stored list.
- `js_json_literal` escapes `<`, `>`, `&`, U+2028 and U+2029, so `</script>` and `<!--` can't break out. Names are already free of control and bidi characters.
- The engine accepts `webgame:controls` only from `window.parent`, as a plain object with at most 32 keys. `applyOverrides` reads only declared ids through `hasOwnProperty`, so `__proto__` keys are inert.
- The parent never takes controls data from the game. Defaults come from the API and overrides from sanitised localStorage.
- The 86-key table is identical in engine, UI and backend (checked against the built dists and `bundle.rs`). Tab, Escape and F-keys are not bindable, so a game can't trap keyboard focus.

**F006 authorization is right.**
- Delete is allowed for the author, the game owner or an admin.
- `remove_comment` resolves the open reports on the comment *and its replies* and deletes them in one transaction. The admin `delete` resolution uses the same function.
- Every read and heart path checks game visibility, so a hidden game reads as an unknown comment.

**F007 has no privacy problems I could find.**
- Visibility is filtered at read time (`published OR owner`, plus at least one event).
- FK cascades remove notifications for deleted games, comments, threads and actors.
- Excerpts are read live, so a deleted comment's text disappears at once.
- Paths are server-built, and the client still filters them through `safeNotificationPath`.

**The F007 write path has a real concurrency bug (M1).** The dedupe branch (hearts, follows, `gamePublished`) opens a deferred transaction with a read and then writes. Under WAL with 8 pooled connections, that fails at once with `SQLITE_BUSY` if any other connection commits in between, and `busy_timeout` does not help. In the `gamePublished` fan-out, the outer transaction keeps the stale snapshot, so **one collision drops the whole 500-recipient chunk**. Both cases are reproduced in the scratch scripts below.

### Scratch evidence (session scratchpad)
- `rv4_snapshot.py` applies all 13 migrations to a WAL file database, then runs two scenarios with `timeout=10`:
  - **Single notify:** conn A runs a deferred `BEGIN` and the dedupe `SELECT`. Conn B commits an unrelated write. Conn A's `INSERT INTO notifications` → **`database is locked` after 0.00 s**.
  - **Fan-out:** an outer `BEGIN` with a SAVEPOINT per recipient (the shape of `fan_out_game_published`), and one concurrent commit after recipient 1's SELECT → **0 inserted, 4 failed**.
- `rv4_migrate.py`:
  - Applies 0001–0009 with `foreign_keys=ON` and seeds users, a game, comments, a follow and a score. Then it applies 0010–0013.
  - Old comments get `parent_id NULL`, and the game is left with `actions_json NULL`, ready for the backfill.
  - Deleting the root cascades to its replies, the replies' hearts, the `reply` notification and its events.
  - An order flip writes a `score_bests_stale` row. `foreign_key_check` is empty and `integrity_check` is `ok`.
- `rv4_prune.py`, on 1M notifications (5000 recipients × 200, every row with an event):
  - **The no-events prune statement takes 5.20 s.**
  - The per-recipient-cap statement takes 0.68 s.
  - Each is a single `DELETE`, so it holds the write lock for that whole time.

## Checked and fine

- **`/play` actions injection (F009).**
  - The source is `game.actions()`, parsed from the stored column and re-serialised by serde, so it is always valid JSON.
  - `js_json_literal` escapes `<`, `>`, `&`, U+2028 and U+2029. Inside the module script, that rules out `</script`, `<!--` and `-->`.
  - `id` and `entry` keep their earlier escaping. The CSP is unchanged.
  - The `/play/studio` page passes `manifest.actions` to the engine's lenient parser.
- **`webgame:controls` trust boundary.**
  - **Engine:** accepts the message only from `window.parent`, requires a plain object with ≤ 32 own keys, applies only declared ids via `hasOwnProperty`, keeps only bindable, de-duplicated codes (max 3), and never overrides gamepad buttons. The change takes effect at the next step without spurious `pressed` edges.
  - **Parent:** sends defaults from the API and sanitised localStorage overrides, only to the verified `iframe.contentWindow`. No game → parent message affects controls.
  - **Key capture:** Tab, Escape and the F-keys are not bindable. Bound keys are `preventDefault`ed only without Ctrl or Meta.
- **The key tables agree across the three implementations.** Engine `BINDABLE_KEYS` (dist), UI `BINDABLE_KEYS` (dist) and `bundle.rs` `BINDABLE_KEYS` are the same 86 codes.
- **The F009 backfill** is idempotent, guarded by `version`, skips `game.json` over 1 MiB, doesn't spin on stuck rows, and runs off the request path.
- **Migrations 0010–0013 on an existing v9 database** (`rv4_migrate.py`):
  - They apply cleanly with `foreign_keys=ON`. `ALTER TABLE ADD COLUMN … REFERENCES` has a NULL default, so SQLite accepts it.
  - The cascades work: root → replies → hearts, notifications and events.
  - `foreign_key_check` and `integrity_check` are clean.
  - No earlier migration was edited (`git diff --stat 2e50b93..HEAD -- backend/migrations` shows only additions), so the sqlx checksums are stable.
- **F006 authorization and validation.**
  - The validation order matches API.md, and the parent comment must belong to the same game (otherwise 404).
  - The reply-cap insert is guarded against both the cap and a root deleted meanwhile.
  - `canDelete` = author, owner or admin, and the server rechecks it in `delete_comment`.
  - `remove_comment` resolves the reports on the comment and its replies in the same transaction as the delete. Admin `delete` uses the same function.
  - Hearts check visibility and then the rate limit. Self-hearts are refused. `INSERT OR IGNORE` guarded by `EXISTS` keeps hearts idempotent, and who hearted a comment is never listed.
- **F007 privacy and contract.**
  - The visibility filter is applied to both list and count.
  - The author of the hearted comment is the only one shown its heart actors.
  - `creatorHeart` follows the current owner.
  - Excerpts are read live and limited to 140 characters (SQLite `substr` counts characters).
  - `mark_read` has the `updatedAt <= upTo` race guard and is scoped to the recipient. Ids that aren't the caller's are ignored.
  - The settings upsert is atomic, and the mute check sits inside the insert.
  - Cursors are base64url, bounded and validated, and `limit`, `unread` and `ids` parsing matches API.md.
  - The handler order is auth → limit → validate.
- **F007 poll loop.**
  - There is one timer per tab, and each next poll is scheduled after the response arrives.
  - Polling pauses while the tab is hidden, unless OS notifications are on (then the interval is 2×).
  - On 429 it waits `max(Retry-After, base)`. Errors back off exponentially, capped at 600 s.
  - 404 hides the bell. A generation counter discards stale responses after a user change.
  - The live region only announces increases.
  - The OS watermark starts at "now" when OS notifications are switched on, and OS notifications are never shown while the window has focus.
  - Mark all uses the newest listed `updatedAt` and no ids, so items beyond the 10 shown are covered too.
- **Bell and threaded comments.**
  - **Bell:** a disclosure with `aria-expanded`. Its name carries the count and the badge is `aria-hidden`. Focus goes to the heading on open, and Escape returns it to the bell. Tab-out and outside clicks close it.
  - **Panel states:** loading, error with Retry, and an empty state. Unread items carry "Unread: " text, so the state isn't conveyed by colour alone.
  - **Comments:** `<article aria-labelledby>`, nested labelled lists, `aria-pressed` hearts, and focus moves on reply, delete and permalink.
- **The slim dev profile** (`line-tables-only` for the crate, no debug info for dependencies) keeps backtraces readable and needs no CI change.
- **Dockerfile:** it still copies `migrations/` and `src/`, and the new modules need nothing else.
- **ci.yml:** the node job auto-discovers the new vitest files, and the backend job's fmt, clippy and test steps cover the new code.
