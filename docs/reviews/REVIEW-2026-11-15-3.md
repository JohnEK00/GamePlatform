## Summary

The review-2 fixes are solid. **11 of 12 are fixed. N12 is fixed, with one nit.** The headline fixes:
- **N2 `score_bests`** is correct and fast. A fuzz of the triggers against a brute-force recompute matched after every one of about 12k random inserts, deletes, order flips, user cascades and game cascades (4 seeds). A board read now takes **0.5 ms at 10k players**, down from 378 ms.
- **Migrations 0008/0009** apply cleanly on a seeded v7 database. The `reports` rebuild keeps every row in rowid order, and the FK and integrity checks pass.

The F005 server pipeline is well built:
- It rate-limits before reading the body.
- It checks size and magic bytes, then reads the header dimensions before decoding.
- It decodes under `Limits`, accepts only an allowlist of formats, and re-encodes, which strips all metadata.
- Media is served with `CSP: sandbox` and `nosniff`.

The F013 download endpoint and the UI zip reader also hold up. The download is owner-only, capped and safe with symlinks. The zip reader enforces its limits on the bytes it actually inflates and cancels the stream early.

The one real security-relevant gap is on the **client side of the screenshot pipeline**:
- `launderImage` hands the game's Blob to `createImageBitmap` *before* it checks any dimensions. A **1 MiB PNG decodes to a 1 GiB bitmap** in the parent page.
- The game-share throttle is **refunded when laundering fails**. So a game can feed the parent decompression bombs back to back, without any user action.

No unsanitised bytes reach an object URL, a download, the clipboard or the server. The weakness is that a game can freeze or crash the viewer's tab (M1).

The other findings:
- **M2:** timing-flaky rate-limit tests. One failed in this session.
- Low-severity items: a11y focus loss in the new dialogs, paging drift, image-decode peak memory, the cost of a score-order rebuild under the write lock, a CI gap for desktop tests, and stale `packages/ui/README.md`.

## Checked and fine

- **`score_bests` correctness (N2):**
  - **Insert trigger:** the row-value tie-break `(rank_score, created_at, score_rowid)` matches `window_board` and `prune_scores`.
  - **Delete trigger:** it promotes the next best only in the deleted row's own `period_start`. Under a game-delete cascade the `JOIN games` finds nothing, so nothing is re-inserted, which is correct.
  - **Order flip:** rebuilds using `NEW.score_order`.
  - **Window keys:** the day key and the ISO-Monday week key (`date(…,'weekday 0','-6 days')`) agree with Rust's `period_bounds`.
  - **Scores and fuzz:** scores are clamped to ±2^53, so `-score` can't overflow. The fuzz covered every path above.
- **Migrations 0008/0009 on an existing database:** they apply after 0001–0007 with data present. The backfill matches brute force. The `reports` rebuild copies every column in rowid order and recreates all 3 indices, and `foreign_key_check` and `integrity_check` come back clean. No earlier migration was edited, so the sqlx checksums are stable.
- **Server screenshot pipeline:**
  - **Before the body:** visibility is checked, then `Limit::Screenshot` is applied before any body is read.
  - **Caption:** read in chunks with a 1 KiB raw cap, rejected unless UTF-8, then checked for scalar count, control characters and bidi controls.
  - **Image validation:** `validate_image` allows at most 2 MB and checks magic bytes. Formats outside the allowlist (PNG, JPEG, WebP) are refused. Header dimensions are checked *before* decoding, and the decode runs under width, height and alloc limits inside `spawn_blocking` behind a `try_acquire` semaphore (503 + `Retry-After`).
  - **Re-encode:** writes pixels only, so text chunks and EXIF are stripped (tested). Alpha is flattened.
  - **Storage:** files are written as temp + rename, and removed again if the guarded `INSERT … SELECT … WHERE COUNT < 20` affects 0 rows or fails. Game deletion removes the files, and the startup sweep removes orphans and `.tmp` files.
  - **Serving:** `/media/screenshots` sends `CSP: sandbox` and `nosniff`, and doesn't cache 404s.
- **Client laundering:**
  - Only the parent's re-encoded PNG ever gets an object URL, a download (`downloadBlob` or desktop `saveFile`), a clipboard write or an upload.
  - The gallery's "Set as thumbnail" launders the server image again.
  - Messages are accepted only from `iframe.contentWindow`. A player reply must match the in-flight `requestId`, and the timeout reads refs when it fires.
  - The caption is sanitised again and rendered as text only.
  - Object URLs are revoked on evict, remove, clear and unmount. The only gap is the DoS in M1.
- **F013 bundle download:**
  - **Access and quota:** `fetch_owned_game`, so a non-owner gets 403 and a hidden unpublished game gets 404. `Limit::BundleDownload` and 2 export slots.
  - **Archive build:** symlinks and non-regular files are skipped. The `CappedWriter` caps the archive at 64 MiB. The version is re-checked after the build (409 on a concurrent replace, retried once by the Studio), and the download never takes the replace claim.
  - **Response:** the ASCII slug keeps the `Content-Disposition` header safe. Headers are `no-store` and `nosniff`. CORS exposes `x-game-version` and `Content-Disposition`.
  - **Re-upload:** a downloaded archive goes through the normal bundle validation (50 MB compressed, 200 MB uncompressed, 2000 files, path rules), so it is no zip-bomb vector.
- **UI zip reader (`unzip.ts`):**
  - **Limits:** they apply to the bytes actually inflated, per chunk, and the stream is cancelled when they're exceeded. Inflating more than the declared `size` aborts.
  - **Integrity:** CRC-32 is verified, along with the stored-size equality.
  - **Refused archives:** ZIP64, encrypted, multi-disk, and methods other than 0/8.
  - **Paths:** absolute, drive-letter and `..` paths are refused, and backslashes are normalised. Duplicates are refused. Local-header and central-directory offsets are bounds-checked.
- **Desktop:**
  - **Folder registry:** random 32-char ids, LRU of 16, in memory only, and the path never reaches the webview. A reload re-runs the same validation, and a vanished folder is forgotten.
  - **`save_file`:** writes only to the path chosen in the dialog. The Pictures or last-folder default is only a hint.
  - **Screenshot menu:** "Take Screenshot" only dispatches `PLAYER_SCREENSHOT_EVENT`, and the CSP allows `blob:` images.
- **Studio autosave fix (`e52a906`):** the debounced timer reads `session.current` when it fires, and `onPublished` updates the ref synchronously before saving, so a stale link can't be written back.
- **Feed (N1):** the UNION de-duplicates by id, both branches apply every visibility filter, and the cursor semantics are unchanged.
- **CI and ops:**
  - The node job builds before testing.
  - The backend uses `--locked`, and MSRV is fine.
  - The Docker build stage has everything F005 needs, and `data/screenshots` is created at startup.
  - The new rate limits are documented in API.md and the backend README.
- **Accessibility done right:**
  - The new dialogs all use `useModal`: focus moves in, Tab is trapped, and Escape is blocked while busy.
  - The gallery has loading (skeleton), empty, error and retry, and load-more-error states.
  - The capture flash respects `prefers-reduced-motion`.
  - Captures are announced through a polite live region, with an NBSP alternation so repeats are announced.
