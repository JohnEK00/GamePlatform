## Summary

**All of review 6 is fixed.** M1, M2 and L1–L5 are fixed and none has regressed. See the status table.

**The F016 core is correct.** I found no leak of `Gamepad.id` and no injection or validation gap:
- **Controller id:** `Gamepad.id` appears only in the in-memory baseline key in `gamepadCapture.ts:119`, `:129`, and the map is cleared in `stop()`. The messages posted to the iframe carry only ids, codes and button names (`controls.ts:652-655`), and `GamePlayer.f016.test.tsx:79-89` asserts this. No other parent code calls `getGamepads()`.
- **Backend:** `routes/controls.rs` validates strictly with the shared `bundle.rs` tables, normalises on both `PUT` and `GET`, and orders checks as the spec says: 401, then 413/400, then 404, then 429, then 422.
- **Engine:** the latch, `lastDevice` and the whole-message rejection of an invalid `gamepad` match GAME_FORMAT § F016.

**The sync hook has one medium race and two lows.** The user/token guard in `useControlsSync` takes the token **when a change is made**, not when the session starts. A cross-tab sign-in as another user replaces the client token before `user` updates. A change made in that window is uploaded into the **other** account, and the original user's unsynced marker is cleared (M1, reproduced). Related lows:
- A skipped upload still shows "Saved to your account" (L1).
- The unsynced marker can be attributed to the wrong person on shared devices (L2).
- Overlapping `PUT`s can leave the server with an older copy while the device marks itself synced (L3).

**F021 keeps private data private.**
- **Events:** they are written only when, inside the add transaction, the collection is public and the game is published (`collections.rs` `announce_add`).
- **Feed:** read time checks again that the collection is public, still owned by the actor, and that each announced game is still in it, added that day and published.
- **Notifications:** they are hidden while the collection is private, and the OS text leaves out the collection title.

Also noted, below the bar for a finding:
- **No `visibilitychange` flush.** Mobile browsers often skip `pagehide` when an app is backgrounded and then killed, so a change made less than 1 s before that is not sent then. The marker stays set and the next mount uploads it, so nothing is lost.
- **Footer copy.** "…it will be retried" is true only on the next change or mount. There is no timer, which the spec says on purpose. "It will be retried next time you play" would be more accurate.
- **The account copy is normalised against the current version.** If the game is updated while a player has the page open (`onGameUpdated`), the `PUT` response is normalised against the *new* actions and written to the device under the *old* defaults. A remap of a renamed action can then vanish from the running (old) game until reload. This is rare and self-correcting.
- **`lastDevice` and multiple pads.** `lastDevice` turns `"gamepad"` for input on any pad, but actions read only the first connected pad (`input.ts:418`, an F009 rule). With a phantom or idle pad at index 0, prompts say "Press A" while that pad's A does nothing. This is pre-existing behaviour, made more visible by `"auto"` labels.
- **The `build.rs` added for the migration rerun isn't copied by the Dockerfile** (`Dockerfile:22-24`). That's harmless, because a clean release build embeds every migration anyway.
- **F021 notification fan-in.** One curator can make up to the collection cap of public collections containing the same game and notify its owner once per collection (rate-limited by `Limit::Collections`). A game mute or the new `collections` setting turns this off. That's acceptable.

## Checked and fine

- **F016 backend** (`routes/controls.rs`, `0020_f016.sql`, `routes/mod.rs`, `ratelimit.rs`):
  - **Order:** `AuthUser` runs before `ApiJson`, so 401 comes first. A 16 KiB `DefaultBodyLimit` sits on the method router (413). Then `fetch_visible_game` (404), then `Limit::Controls` 60/60 s per user (429), then strict validation (422).
  - **Rate limit:** the order matches API § F016 and spec § 3.4. A 422 uses up a token, as documented.
  - **Validation:** it rejects a non-object `bindings`, non-object sections, more than 32 ids, bad ids, non-array values (including `null`, as noted in the docs), non-strings, unknown or `Home` names, over-long lists and duplicates. Error paths match the documented strings.
  - **Normalisation:** manifest order, undeclared ids and entries equal to the defaults are dropped, and an empty result stays a row. A corrupt stored row reads as `null` and logs a warning.
  - **Schema:** the composite PK covers every lookup, `idx_control_bindings_game` serves the game cascade, and the user cascade uses the PK prefix.
  - **Serialisation:** `ControlBindings` serialises in manifest order through `OrderedMap`. CORS allows `PUT`.
- **F016 engine:**
  - `applyOverrides` uses replace semantics, with `[]` clearing a binding and an absent `gamepad` restoring the defaults. An invalid `gamepad` rejects the whole message (`engine.ts:355-358`).
  - **Latch:** it is consumed by the next poll even without a pad, and steps don't poll while paused (`engine.ts:457`). A held captured button therefore can't fire `pressed` after `webgame:resume`. `ActionMap` is edge-based, so actions respect the latch too.
  - **`lastDevice`:** key repeat, movement, the wheel and cancelled releases don't change it, and gamepads win a same-step tie. `setActions` clears both override sets.
  - **Examples:** Pixel Peaks and Space Dodge use `"auto"` labels. No example reads raw buttons for declared actions; Ember Garden only checks `connected`.
- **F016 UI capture:**
  - **One capture at a time:** `claimCapture` enforces it across key and gamepad slots.
  - **Escape:** the gamepad capture's window-capture `keydown` handler runs before `useModal`'s document-capture handler, so Escape cancels capture without closing the dialog.
  - **Baselines:** each pad has its own baseline, a first sighting counts as baseline, and non-standard mappings and `Home` produce messages. A missing API or a `SecurityError` ends capture with the "unavailable" note.
  - **Focus:** focus is kept when × clears a slot, and Reset and Reset all move focus before they unmount.
- **F016 sync, except M1–L3:**
  - **`GET` versus local edits:** a change made while the `GET` is in flight wins over the account copy (`:135`).
  - **Clearing the marker:** it is cleared only when the device still equals what was sent.
  - **Sign-out and switches:** sign-out, and a direct A→B switch in the same tab, send nothing and keep A's marker (`currentUser` is updated during render, before the cleanup flush).
  - **Flushes:** the unmount and `pagehide` flushes use keepalive, within the quota check in `ApiClient.request`.
  - **Other callers:** games without actions never call the endpoints, and the Studio keeps bindings in memory only.
  - **Writes:** marker-only writes don't notify, so no duplicate `webgame:controls` is sent.
- **Desktop:** `tauriConfig.test.ts` checks that `connect-src` and `frame-src` allow the configured server, and that no Permissions-Policy header or WebView2 argument disables gamepads.
- **Migration 0019 (F021):** `activity_events` is rebuilt with the AUTOINCREMENT high-water mark carried over and the indexes recreated, plus a partial `idx_activity_collection`. `CHECK (game_id IS NOT NULL OR collection_id IS NOT NULL)` holds. Nothing references `activity_events` and it has no triggers, so the drop cascades nothing. The new `notifications.collection_id` FK cascades on collection delete.
- **F021 feed:** branch (c) applies every rule in SQL, so pages aren't under-filled. Branch (a) drops `collectionUpdated` rows through its `games` join (`game_id` is NULL). Assembly is batched (games, collections and items in three queries). Notes and titles render as React text.
- **F021 notifications:**
  - **Visibility:** they are hidden through the shared visibility filter (list and count) while the collection is private or deleted.
  - **Withdrawal:** an unread notification is withdrawn on remove and restored on re-add.
  - **Mutes and settings:** game mutes and the `collections` setting apply, and the curator's own game is skipped.
  - **OS text:** `osNotificationText` leaves out the collection title.
- **Ops:** the Dockerfile copies `backend/migrations` before `cargo build --release --locked`, so 0018–0020 are embedded. `.dockerignore` excludes `data`, `*.db*` and `.env`. No workflow changes since round 6.
